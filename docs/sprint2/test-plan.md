# План тестування «АвтоРейт» — спринт 2

План підготував: Кінаш Єгор (ІТ). Відповідальна за узгодження: Дарина Поломарьова (КТ).

Версія 1.0 • 13.10.2026 • Основа: виправлена SRS 1.1, продукт П5.

## 1. Продукт і межі тестування

Перевіряємо вебкаталог «АвтоРейт» (Buggy Cars Rating), сценарії реєстрації, входу, голосування за модель з коментарем, рейтингу, профілю, пагінації та модуль Java `autorate-module` (`RatingAggregator`, `VoteValidator`, `ModelSearch`). Окремо плануємо перевірки нової функції «Особистий кабінет і рейтинг тижня». Не перевіряємо інтерфейс адміністратора чи модератора, мобільний застосунок і непідтверджені інтеграції з державними реєстрами.

Публічне demo https://buggy.justtestit.org/ придатне для ручних сценаріїв UI та smoke. Важкі перевірки навантаження, конкуренції, захищеності — тільки на локальному/дозволеному тестовому середовищі. DemoQA — лише резерв для UI-форм за рішенням викладача.

## 4. Незастосовні типи

Не включаємо до основних прогонів інсталяційне (вебсервіс без установника), доступності з резервуванням (не задана архітектура), failover (немає резервних вузлів) та локалізації (UI тільки англійською). Для кожного типу причина зазначена в таблиці розділу 3. Це не означає, що команда не перевірятиме звичайний запуск, відновлення сторінки чи кирилицю в коментарях: для них передбачені smoke, надійність та інтернаціоналізація.

## 5. Інструменти, середовище і тестові дані

- **Веб:** Chrome і Firefox, Windows 11 або Linux, активний JavaScript; публічний https://buggy.justtestit.org/ для безпечних ручних кейсів.
- **Модуль:** Java 17, Maven 3.9, JUnit 5, підготовлені масиви `Vote` та `CarModel` (1/3/5 голосів, рівні рейтинги, null, граничні оцінки).
- **Локальні перевірки:** JMeter або k6 для навантаження; JFR/JVisualVM для часу й пам’яті; ізольована копія системи і тестова БД тільки за наявності доступу.
- **Облікові записи:** 3–4 вигадані користувачі з унікальним префіксом команди `FB44-S2-`; не використовувати персональні дані. Паролі спільних demo-акаунтів не змінювати.
- **Контроль даних:** до і після голосу фіксується відносна зміна лічильника на 1, а не абсолютна кількість; для повторного тесту брати іншу модель або іншого користувача.
- **Продуктивність:** контрольовані умови P-10/P-20; p95 за 30 замірами; обсяг каталогу максимум 1 000 моделей. Не запускати навантаження на public demo.

## 6. Ризики і припущення

| Ризик / припущення | Вплив | Дія |
|---|---|---|
| Demo може бути недоступним або скидати записи | Частина UI-кейсів blocked | Занести час і причину, повідомити викладача; самостійно не переходити на DemoQA. |
| Один голос на модель | Повторний позитивний тест блокується | Підготувати кілька моделей / акаунтів, не видаляти чужі дані. |
| Тижневий топ і історія голосів не представлені повністю у demo | Неможливо виконати повний приймальний сценарій зараз | Запланувати кейси за BL та SRS; у спринті 3 позначити заблоковані/не застосовні до demo. |
| Поріг 3 голоси, пароль, таймаут і числові метрики у SRS 1.1 можуть потребувати підтвердження | Зміна очікуваних результатів | Поставити питання замовнику до формування остаточних тест-кейсів. |
| Не надано власного продакшн-стенду і резервної інфраструктури | Частина тестів лише в плані | Локальний стенд створюється тільки після дозволу і отримання параметрів розгортання. |
