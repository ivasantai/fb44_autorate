# План тестування «АвтоРейт» — спринт 2

План підготував: Кінаш Єгор (ІТ). Відповідальна за узгодження: Дарина Поломарьова (КТ).

Версія 1.0 • 14.10.2026 • Основа: виправлена SRS 1.1, продукт П5.

## 1. Продукт і межі тестування

Перевіряємо вебкаталог «АвтоРейт» (Buggy Cars Rating), сценарії реєстрації, входу, голосування за модель з коментарем, рейтингу, профілю, пагінації та модуль Java `autorate-module` (`RatingAggregator`, `VoteValidator`, `ModelSearch`). Окремо плануємо перевірки нової функції «Особистий кабінет і рейтинг тижня». Не перевіряємо інтерфейс адміністратора чи модератора, мобільний застосунок і непідтверджені інтеграції з державними реєстрами.

Публічне demo https://buggy.justtestit.org/ придатне для ручних сценаріїв UI та smoke. Важкі перевірки навантаження, конкуренції, захищеності — тільки на локальному/дозволеному тестовому середовищі. DemoQA — лише резерв для UI-форм за рішенням викладача. 

Зараз доступні ручні UI/smoke-перевірки demo та спостереження його звичайних запитів у DevTools. Перевірки Java-модуля починаються після отримання `autorate-module` у спринті 4; його вихідних файлів у цьому репозиторії немає. Ізольований вебстенд і БД поки не надані, тому відповідні перевірки мають статус «заблоковано», а не «незастосовно». Умови гонок залишаються High і мають бути перевірені після появи API/БД до приймання нової функції.

## 4. Незастосовні типи

Не включаємо до основних прогонів інсталяційне (вебсервіс без установника), доступності з резервуванням (не задана архітектура), failover (немає резервних вузлів) та локалізації (UI тільки англійською). Для кожного типу причина зазначена в таблиці розділу 3. Це не означає, що команда не перевірятиме звичайний запуск, відновлення сторінки чи кирилицю в коментарях: для них передбачені smoke, надійність та інтернаціоналізація.
