# Питання замовнику та спірні рішення

За уточнення суперечливих вимог відповідає Дарина Поломарьова (КТ); редакцію SRS готує Асташов Іван (ТА). Нижче — питання, які варто закрити до написання тест-кейсів у спринті 3. Робоче рішення вже відображене в SRS 1.1, але його необхідно підтвердити.

| № | Вимога | Питання | Робоче рішення / аргумент | Стан |
|---|---|---|---|---|
| Q-01 | F-130 / BL-20 | Мінімум голосів — 3 чи 5? | Прийнято 3, оскільки саме так формулюється BL-20, який тестуватиметься JUnit. | Підтвердити замовником |
| Q-02 | F-60 / F-130 | Ранг залежить від голосів чи зваженої оцінки? | Для рангу — зважений рейтинг за BL-10; Popular Model за кількістю голосів (F-10). | Підтвердити замовником |
| Q-03 | F-30 | Яка точна складність пароля? | 8–64 символи, латинська літера і цифра; потрібне підтвердження відповідності demo. | Підтвердити замовником |

## Три дефекти для показу на Demo

1. **Найочевидніший:** RD-14 — двічі `GUI-40`; друга вимога отримала `GUI-45`.
2. **Спірний:** RD-11 — 5 голосів у F-130 проти 3 у BL-20; обране правило потрібно узгодити.
3. **Критичний для наступних спринтів:** RD-10 — BL-50 дозволяє порожній коментар, хоча F-90 вимагає коментар до голосу. Через це тест-кейси API та UI суперечили б один одному.
