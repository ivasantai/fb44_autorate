## Рішення на наступний спринт

| № | Дія | Відповідальний |
| --- | --- | --- |
| 1 | На початку прогону підготувати власні тестові записи та моделі для голосування; кожен кейс створює свій початковий стан. | Асташов Іван |
| 2 | Для числових обмежень застосовувати нижню/верхню межу та сусідні недопустимі значення. | Дарина Поломарьова |
| 3 | Не змішувати клієнтську валідацію та серверне прийняття; вказувати точний перевірений крок. | Кінаш Єгор |
| 4 | Для голосування порівнювати приріст зі збереженим V та враховувати одночасні зміни. | Асташов Іван |
| 5 | Зберегти TC-NNN та BUG-NNN у спринтах 4–5; не перенумеровувати наявні записи. | Рушай Євген |
| 6 | Зберегти звичайні колонки, одну матрицю покриття та один реєстр дефектів. | Кінаш Єгор |
